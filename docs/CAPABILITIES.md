# 能力与边界

这份文档只有一个目的：**让你在用它之前就知道它会在哪里错。**

一句话定位：它把 Windows 对"这个文件的签名"的判断，拆成一条能看懂的证据链；
它**不**证明文件安全，**不**修复任何东西，也**不**替代发布者给出的哈希。

---

## 一、能做什么

| 能力 | 具体行为 | 怎么验证它真的做了 |
|---|---|---|
| 区分签名形态 | 嵌入式签名 / 目录签名（catalog）/ 两者都没有 | 对 `cmd.exe` 跑一次，应得 `catalog_only_trust` |
| 给出精确错误码 | 调 `WinVerifyTrust` 拿 HRESULT，不满足于 `Valid/NotTrusted` | 报告里出现 `0x800B0100` 这类十六进制码 |
| 区分"证书坏了"与"网络不通" | 探测 CRL/OCSP 可达性，结合链标志 | `--no-probe` 与默认输出的差异 |
| 检查目录签名自身状态 | 读到 `.cat` 后，还看 `.cat` 的签名是否 `Valid` | 报告里的「目录签名状态」 |
| 时间戳令牌校验 | 解 PKCS#7，把令牌当独立 SignedCms 验签 | `--timestamp` 后出现「时间戳令牌：验证通过」 |
| 吊销检查（四档） | `off/cache/auto/online`，`auto` 先探路再决定 | `--revoke=auto` 的报告行「吊销：已检查」 |
| 识别文件损坏 | MZ/PE 头校验、证书表越界、签名后追加数据 | 截断样本 → `corrupt_pe`；尾部追加 → 证据里多一行 |
| 批量与流水线 | 目录扫描、NDJSON 流式、固定 JSON 结构、退出码 | `--json` 输出的顶层键固定 |

## 二、不能做什么

| 做不到 | 为什么 | 替代手段 |
|---|---|---|
| 证明程序安全、不含漏洞 | 签名只说明"谁发布、发布后有没有被改" | 沙箱、代码审计、发布者哈希 |
| 检测 API 层绕过 | 它报告的是 Windows 的结论，系统被绕过它也看不出来 | 独立哈希比对、`signtool verify /pa /v` |
| 独立完成密码学校验 | ASN.1/PKCS#7 解析全部交给 Windows | 需要独立实现时用 osslsigncode 等 |
| 验证时间戳"绑定"与 TSA 链 | 只验令牌签名，未验 messageImprint / EKU / TSA 时效 | `signtool verify /pa /t` |
| 修复、隔离、删除 | 只读设计 | 手动处置 |
| 网络取证 | 只判断 CRL/OCSP 地址可达性 | 抓包、代理日志 |
| 跨平台 | 全是 Windows API 与 PowerShell | — |
| 覆盖所有文件类型 | 只对 PE 做深判；脚本/msi 只看粗状态 | 对应平台的专用工具 |

## 三、什么时候准确

| 场景 | 结论 | 置信度 | 备注 |
|---|---|---|---|
| 正常嵌入签名、链完整、未过期 | `valid_revocation_unchecked`（默认档）或 `checked_ok` | medium / high | 默认档不含吊销 |
| 签名后内容被改 | `hresult:TRUST_E_BAD_DIGEST` / `invalid` | high | 最可靠的一类 |
| 系统组件（目录签名） | `catalog_only_trust` | high | 已校验 `.cat` 自身状态 |
| 证书过期但时间戳令牌验签通过 | `expired_with_timestamp_signature_ok` | medium | 只证明令牌未被篡改 |
| 确实没有签名 | `no_signature` | high | ≠ 被篡改 |
| 文件被截断/头损坏 | `corrupt_pe` / `not_pe_file` | medium | 先重新下载 |
| 吊销状态真查到了 | `valid_revocation_checked_ok` / `revoked` | high | 需要 `--revoke≠off` |

## 四、什么时候不准确（已知，不是意外）

| 情况 | 会错在哪 | 严重度 |
|---|---|---|
| 中间 CA 过期 | 会按"签名者证书过期"叙述 | 中 |
| 证书"尚未生效"（本机时间超前） | 同上，混进"过期"分支 | 中 |
| 同一文件既有嵌入签名又有 catalog | 两套证据可能回答的不是同一个问题，未标注来源 | 中高 |
| `--revoke=cache` 未命中 | 结论是"未检查"，不是"通过" | 低（措辞已明确） |
| 时间戳 | 只验令牌签名，"有效"≠"可信时间戳" | 中 |
| 真实吊销样本 | `revoked` 分支从未被真实数据触发过 | 中 |
| 企业代理 / PAC | 只支持显式 HTTP/HTTPS 代理，PAC 不求值 | 中 |
| 非 Windows 11 | 只在 22621 验证过 | 中 |
| 慢网络 + `--revoke=online` | WinVerifyTrust 无超时，可能卡住 | 中 |
| 驱动安装类失败（`0x800F0242` / `0xE0000243`） | 这类错误发生在安装上下文的 catalog 成员校验，工具只验证 `.cat` 自身签名，答不了"为什么这个发布者没被信任" | 高（运维场景） |
| 合法签名被 API 误报 `TRUST_E_MALFORMED_SIGNATURE` | 现在归为 `malformed_signature` / unknown，不再报 valid，但工具无法判断真伪 | 中 |
| 交叉根只带时间戳 EKU | 现在归为 `wrong_usage` / invalid，但不会指出是哪一级证书的 EKU | 中 |

完整清单见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。

## 五、它自身什么时候是安全的

- **只读**：不安装证书、不改注册表、不加白名单、不绕过校验
- **不联网以外的副作用**：不上传文件、不写系统目录
- **网络范围受限**：只访问证书里写明的 CRL/OCSP 地址；解析后若落在内网/回环段**默认不探测**
- **不跟随重定向**：避免被 302 引到内网地址
- **UI 只监听 127.0.0.1**，并校验 `Host` 与 `Origin`
- **便携包**：构建时用本项目自己的 WinVerifyTrust 校验运行时 `python.exe` 的签名
- **发布可核验**：Release 附 `SHA256SUMS.txt`

## 六、什么时候你该小心

| 场景 | 风险 | 建议 |
|---|---|---|
| 扫描来路不明的文件 | 会读取并解析恶意 PE；ASN.1 解析由系统完成，但仍是不受信输入 | 用 `--offline --no-probe`，在虚拟机里跑 |
| 在敏感网络批量扫陌生文件 | 会对外发请求（尽管禁止内网地址） | `--offline`，或先看报告里的探测目标 |
| 用 `--ui` 时 | 同机恶意网页可能触发扫描（有 Host/Origin 校验，但无 token） | 用完关掉；不要开着界面逛不可信站点 |
| 把 `valid` 当发布门禁 | 它只覆盖"签名"这一项 | 加 `--require-signature`，并配合哈希比对 |
| 从非官方渠道拿二进制 | 可能被替换 | 只从 Release 下载，核对 `SHA256SUMS.txt` |
| 在断网机器上跑 `--revoke=online` | 会等待超时 | 用 `--offline` 或 `off` 档 |

## 七、证据强度分级（用它来读结论）

| 级别 | 什么样的结论 | 该怎么对待 |
|---|---|---|
| A | 明确 HRESULT（哈希不匹配、显式不信任、已吊销） | 可直接采信 |
| B | 链与签名通过（含目录签名 Valid） | 依赖系统信任库；信任库被改过则结论失效 |
| C | 时间戳令牌验签通过 | 只说明令牌未被篡改 |
| D | `unchecked` / `unknown` / 探测不可达 | **只是"没查到"**，不能当"有问题"，也不能当"没问题" |

## 八、推荐的判断流程

```
1. 文件坏了没？（corrupt_pe / not_pe_file）
      → 先重新下载，别谈签名
2. 有明确错误码吗？（hresult:*）
      → A 级证据，直接按错误码处置
3. 是目录签名吗？（catalog_only_trust）
      → 正常，但要确认 .cat 自身状态是 Valid
4. 只有"未检查/不确定"？
      → 加 --revoke=auto 再跑；仍不确定就换网络或离线复核
5. 仍然拿不到结论？
      → 用 signtool verify /pa /v 或发布者哈希交叉验证
```

## 九、证据状态

哪些结论经过真实样本验证、哪些只是构造输入，见 [MAINTAINING.md](MAINTAINING.md) 的「证据边界」。
**改动代码后请同步更新那一节**——这份文档的价值全在"如实的部分"是否跟得上代码。
