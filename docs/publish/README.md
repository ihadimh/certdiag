## 掘金（技术优先）

**标题**

> Windows 代码签名诊断：为什么 `cmd.exe` 没有签名却"有效"，以及 `unknown ≠ invalid`

**摘要**

> 一次 qsvg.dll 的真实排查，带出 Windows 签名校验的三个坑：目录签名与嵌入签名的
> API 差异、过期证书 + 时间戳的判定逻辑、以及把"吊销查不到"当成"证书有问题"的误判。

**标签**：`Windows` `安全` `证书` `PowerShell` `排查`

**开头替换**（掘金版，先给结论）

```
先给结论：Windows 报"签名无效"至少有四类原因，处置方式互相矛盾。

  1. 网络问题（吊销查不到）→ 换网络，别删证书
  2. 目录签名（签名不在文件里）→ 查 .cat，别重装
  3. 证书过期 + 有时间戳 → 仍可能有效
  4. 根证书不受信 → 装中间证书

下面用一个真实案例说明为什么第 1 类最容易被误判。
```
