# 已知未修问题（KNOWN_ISSUES）

> 用途：**诚实清单**。已知、但还没修的问题。
> 不要把"没修"当成"不存在"——这份清单就是用来防止这件事的。

严重度：**P1** 会给出错误结论 · **P2** 特定场景下不准确 · **P3** 工程性

## P1

### 1. 「已吊销」结论从未被真实数据验证
`revoked` 分支只在单元测试里用构造输入跑过。手上没有一张确定被吊销的代码签名证书样本。

**影响**：真遇到被吊销的文件，不确定能否正确触发。
**怎么补**：找一张已知吊销的证书签的 exe；或导出签名者证书后用 `certutil -verify -urlfetch <证书.cer>` 对比链与吊销结果。

### 2. `NotTimeValid` 不区分是哪一级证书的时间问题
现在只要链上有 `NotTimeValid` 或签名者证书 `NotAfter` 过期，就按"签名者证书过期"处理。

**影响**：中间 CA 过期、或本机时间超前（证书"尚未生效"）会被误述。
**怎么补**：保留 `ChainElementStatus` 的层级信息，按证书逐个判断（要改 collect→attrib 的数据流）。

### 3. WinVerifyTrust 没有超时保护
`online` 档可能卡住（同步 API，没有超时参数）。

**影响**：慢网络/CA 无响应时用户会以为程序挂了。
**怎么补**：放进独立子进程，父进程超时后杀掉。

### 10. 驱动安装上下文的 catalog 失败无法归因
`0x800F0242`（SPAPI_E_AUTHENTICODE_TRUST_NOT_ESTABLISHED）与 `0xE0000243` 发生在驱动安装时的
catalog 成员校验与发布者信任建立阶段。工具只验证 `.cat` 自身签名，答不了"为什么这个发布者没被信任"。

**影响**：运维场景下只能确认"有个 .cat"，不能给出根因。
**怎么补**：走 `WINTRUST_CATALOG_INFO` 路径校验成员与发布者信任链，并解析安装上下文错误码。

## P2

### 4. `auto` 档用普通 HTTP 探测决定是否联网查
OCSP 只接受 POST，GET/HEAD 失败会被判为 `inconclusive`，`auto` 可能因此跳过真正的检查。

**影响**：本该查的场景没查（但会如实写"未检查"）。
**怎么补**：区分"预检结果"与"实际检查结果"，不要用前者决定后者。

### 5. GUI 没有 `--revoke` 选项
界面固定用默认 `off`，用户不知道报告里的"未检查"是默认值。

### 6. 代理只支持显式 HTTP/HTTPS
`ProxyOverride` 绕过列表、PAC 求值、SOCKS 都不完整。README 已写明限制。

### 7. 时间戳的 `messageImprint` 未校验
只验令牌签名，没有验证"这个令牌确实对应当前文件的签名"。README 已列出。

## P3

### 8. 测试覆盖仍偏重归因函数
86 个用例里只有 5 个真调 Windows API（WinVerifyTrust / Catalog / 时间戳）。
网络探测、代理、批量 UI 仍无自动化测试。

### 9. 只在 Windows 11 22621 上验证过
没有在 Win10 / Server / 精简系统上跑过。
